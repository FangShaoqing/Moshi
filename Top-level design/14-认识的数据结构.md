# 14 · 一条"认识/倾向"的数据结构（最小可校验单元）

> 记录日期：2026-08-27（会话进行中）
> 状态：**草案 / 待拍板**。这是 ΔS=丙 的最小产物单元，也是"人格从经历中涌现"的载体。
> 定位：整个"孕育一个人"的最小可校验单元——定了它，"事件→认识映射"和"强度"才有落脚点。
> 原则：非标签（有因果、可解释）、可累积、可矛盾（厚度）、可回溯（挂在经历上）、可校验。

---

## 〇、一条认识要回答的三个问题

它必须能表述清楚"她因为什么、在什么情境下、会倾向怎么做、倾向多深"。即：

```
她 因为 [经历X]  →  在 [情境Y] 下  →  倾向于 [做法Z]  →  强度 [I]
```

---

## 一、数据结构草案

```text
Belief / Disposition（一条认识/倾向）
├─ id            唯一标识
├─ cause         触发经历：哪段/哪些经历形成或强化了它      ← 因果可溯
├─ domain        情境域：这条认识关于"哪个情境/对象/关系"    ← 非标签的关键（限定对象）
├─ tendency      倾向：在该情境域下她倾向于如何行动/反应     ← 可读、可解释（不是形容词）
├─ attribution   归因：她为什么这样想（她对这段经历的解读）   ← "为何如此"的解释
├─ strength      强度：多牢固、多影响后续（建议 0~1）
├─ salience      活跃度：此刻这条认识在她的心理中有多重要    ← 影响"此刻行为"，可与 strength 分离
├─ affect        情感色调：它带的情感倾向（如 VAD 三轴）
├─ formed_at     形成时间/年龄
└─ tension       张力：与哪些其他认识存在张力/矛盾          ← 厚度/优秀线
```

---

## 二、关键设计点（为什么这些字段能保"非标签"）

- **重点在 `cause` + `domain` + `tendency` 三者的组合**，而不是一个孤立形容词。
  - 不是"她=谨慎"（标签），而是"**因为经历了被背叛（cause），所以她（在面对亲密关系时 domain）倾向于先留三分（tendency）**"。
  - 这才是"有因果、条件式、可解释"的倾向，而非静态特质判断。
- **`tendency` 不必是"性格词"，而可以是"一种可观察的做法/态度"**——甚至可以是行为倾向（"会先试探、会保留"）。
- **`tension` 允许矛盾**：人可同时有"想靠近"和"怕受伤"两条认识——这累积出立体感/厚度，正是优秀线。
- **`cause` 挂在经历上**：每条认识都能说清"来自哪段经历"，支持"她为何如此"的因果回溯。

---

## 三、需要协作方拍板的几个决策点

我一直避免替你过度设计，所以这里有 3 个权衡点需要你来定方向：

### 决策点 1：`strength` 和 `salience` 要不要分开？
- **分开**（我倾向）：`strength` 是"这条认识有多牢固"（长期，慢），`salience` 是"此刻她有多想起它"（短期，随情境波动）。它能支持"平时不活跃、特定时刻突然强烈"的真实感。
- **合并**：一个值就行，简单，但少了"平时被压着、遇事爆发"的层次。

### 决策点 2：`tendency` 是"自由文本"还是"受控词表"？（✅ 我主张 = 折衷）
**完整的、唯一的立场：`domain` 完全受控；`tendency` = "受控候选为主 + 约束下有限度自由"，并保留一致性校验。**

- **为什么不是完全自由**：完全自由文本最细腻，但难做一致性校验、难对比、累积多了会乱。
- **为什么不是完全受控**：完全受控词表太粗，会漏掉很细、很个人化的倾向（如"她会先找借口不立刻答复，其实是在观察对方态度"——硬塞进一个词就丢了细腻）。
- **折衷如何落实**：
  - `domain`（情境域）：**结构性强、可穷举**（关系/工作/金钱/亲密…）→ 铁定用受控词表；
  - `tendency`（倾向）：**本质是"质感"** → 词表管大类，细节允许在词表约束下有限度自由，节点上保留一致性校验。
- **本质**：这就是原则"**结构归算法、质感归大模型、大模型不发明结构**"的具体化——`domain` 是结构（算法定），`tendency` 是质感（大模型在约束下填）。

### 决策点 3：`affect`（情感色调）要不要纳入一条认识？
- 认识往往带着情感（"被背叛"这条认识本身是刺痛和警惕），纳入 affect 能让"情感"与"倾向"绑定，更立体。
- 但也可能让结构变复杂。也可把情感**单独放在"情绪状态"里**，而不放进每条认识。（这与 VAD 引擎相关，可留到后面。）

---

## 四、最终定型（✅ 协作方已全部确认）

**"一条认识/倾向"（Belief/Disposition）= ΔS=丙 的最小产物单元。**

三个决策点最终结论：
1. **`strength` / `salience` 分开**：`strength`=多牢固（长期慢），`salience`=此刻多活跃（短期，随情境波动），支持"平时压着、遇事爆发"。
2. **`tendency` 用折衷**：`domain` 完全受控（结构，算法定）；`tendency` 受控候选为主 + 约束下有限自由 + 保留一致性校验（质感，大模型填）。本质 = "结构归算法、质感归大模型"。
3. **`affect` 先不放进每条认识**：放"情绪状态"里，减负，后面再考虑合并。

**定型的 "Belief" 结构（字段清单）：**
```text
Belief / Disposition
├─ id            唯一标识
├─ cause         触发经历（哪段经历形成/强化了它）       ← 因果可溯
├─ domain        情境域（受控词表：关系/工作/金钱/亲密…） ← 完全受控
├─ tendency      倾向（受控候选为主 + 约束下有限自由）    ← 可读、可解释（非形容词）
├─ attribution   归因（她为什么这样想）                  ← "为何如此"的解释
├─ strength      强度（多牢固，0~1；慢变量）
├─ salience      活跃度（此刻多活跃；随情境波动，快变量）
├─ formed_at     形成时间/年龄
└─ tension       张力（与哪些认识矛盾）                  ← 厚度/优秀线
```

**这条"认识"同时满足**：非标签（cause+domain+tendency 组合，条件式而非判断句）、涌现（由经历决定）、因果可溯（挂在 cause 上）、厚度/优秀线（tension 允许矛盾）、可校验（domain 受控）、可累积（独立单元）。**这是整个项目"人格从经历中涌现"的最小可校验单元。**
