# 38 · 依恋机制（演化而非预设；是否依恋由她的想法+相处决定）

> 记录日期：2026-08-31（会话进行中）
> 状态：已实现并实测 ✅（混沌敏感保持 12.2 亿倍 / 生成正常）
> 定位：协作方明确——"**不要刻意往'依恋我'的方向做，而是要做出演化机制，是否依恋我由相处过程和默识的想法决定。**"
> 本机制正是如此：依恋**不是预设/迎合**，而是机制演化结果 + 她自己的性格。

---

## 〇、为什么不是"数值信任"而是"依恋机制"

- 市面 AI 的"信任"是**一个数值**（0.8 = 更信任）；
- 真实的关系里，信任不是数值，是**依恋**（她会开始在意你、怕失去你、会不会主动你、你冷淡时她的反应——由依恋状态决定，且**她可能不依恋**）。

## 一、机制（person.py）

**两个连续值（0~1），由演化驱动：**
| 值 | 含义 |
|----|------|
| `security` | 她觉得"跟你在一起是安全的" |
| `dependence` | 她有多在意你/需要你 |

**演化函数 `update_attachment(warmth, hurt, stability, absence)`：**
- **稳定温暖** → security↑、dependence 缓慢↑；
- **伤害** → security↓；dependence 按现状分化（已高→焦虑型更依赖；还没起来→回避型退缩）；
- **忽冷忽热** → security↓（不稳→焦虑）；
- **长期缺席** → dependence↓（她学会不需要你）。

**性格引力（关键——她未必依恋）：**
- 若她的性格认识里有"信任难/留三分/稀缺"倾向 → **dependence 上限 0.6、security 上限 0.65**（持续约束）：
  **一个本性难信任的人，不会因为你对她好就完全变安全/交心**——她会有点在意，但**仍观望**。

**`attachment_style()` 推导类型**：安全型 / 焦虑型 / 回避型 / 矛盾型 / 独立型 / 观望型。

## 二、实测（✅ 演化正确 + 她未必依恋）

| 相处方式 | 结果 |
|---------|------|
| 稳定温暖 ×20 | security=1.0 dependence=1.0 → **安全型**（依恋） |
| 忽冷忽热 ×20 | security=0 dependence=1.0 → **焦虑型**（怕失去又离不开） |
| 持续伤害 ×15 | security=0 dependence=0 → **回避型**（缩回、不需要你） |
| 低信任性格 + 温暖 ×20 | security=0.65（上限） dependence=0.6（上限） → **观望型**——**她不轻易交心，由她本性决定** |

**关键**：最后一行——**一个本性难信任的她，你对她好 20 次，她"有些在意但仍观望"，不会"依恋你"**。这验证了"是否依恋由她的想法+相处决定"，**不是脚本化地"她应该依恋我"**。

## 三、注入 LLM（对话中自然显现，不刻意）

`attachment_context`：给 LLM 她的依恋状态（安全型→稳妥不黏；焦虑型→会不安/需要确认；回避型→退缩/不太依赖；观望型→在观察）——**她会不会主动、你冷淡时什么反应、会不会怕失去你，都由此决定**。

## 四、持久化（跨会话延续）
`security / dependence` 存入 state.json，恢复——**她上次"焦虑中/回避型"，下次还是**。

---

## 五、意义
- **依恋是演化出来的，不是设定的**——她依恋你与否，是"你们真实相处 + 她本性"的共同结果；
- **她可能不依恋你**（本性回避/你不够好）——这才是真实（真实的人不会因为你追她就爱你）；
- **与"无限逼近真实"哲学一致**：机制真实、演化真实、结果由关系与性格决定。
