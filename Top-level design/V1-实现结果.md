> 记录日期：2026-08-30（会话进行中）
> 性质：V1 最小生命引擎（Python 纯算法、不接大模型）。核心：**去掉手写，让算法系统自己孕育一个人**，并验证"确定性混沌 + 先在条件生发 + 人格涌现"。
> 前置：V0（验证灵魂载体）、Top-level design/ 01-14 设计；运行 `python -m moshi.v1_demo`。

## 一、V1 验证的三个核心目标（全部通过 ✅）

| 目标 | 验证点 | 结果 |
|------|--------|------|
| **确定性混沌** | **同种子 → 完全同一个人**（可复现） | ✅ 种子=20260827 生成两次，人格签名相等=True |
| **混沌敏感依赖** | **近种子（±1）→ 完全不同的人生 + 不同先在条件** | ✅ seed±1 均长出不同先在条件、不同人格 |
| **先在条件生发** | 先在条件由系统从合法状态格生成，**非造物主设定** | ✅ 同一个"时代锚"下，不同种子选中不同城市/家庭阶层/氛围 |
| **人格涌现（非标签）** | 认识是"因为[经历]，所以在[情境]上倾向[做法]"的条件式 | ✅ 每条都是条件式，非形容词判断句 |
| **具体感（良好线）** | 事件描述有地点/家庭氛围/年龄/走向，而非抽象占位 | ✅ 如"5岁，身边一个亲近的人（动荡氛围长大）做出一件让她不敢再轻易托付的事" |

## 三、确定性混沌怎么实现的（关键）

- 用 `random.Random(seed)` 初始化一个**确定性 PRNG**（同 seed → 同序列），保证可复现。
- **先在条件**：由 PRNG 在真实候选池里选（不同种子 → 不同城市/阶层/氛围/出生年）。
- **L2 推进器**：每一步按 PRNG + 先在条件"拉偏"决定"哪个领域发生大事" → 生成有质感的具象事件 → 反哺出认识（带强度）。
- **混沌的本体**：每步的"认识强度"有个 `_drift` 扰动累积，且**每一步都依赖之前的结果**（路径依赖）+ PRNG 序列。于是 **seed 一微扰 → 先在条件不同 → 之后链条全变 → 不同人生**。
- **近似而非严格**（符合 10 的简化原则）：不是真正的 Lyapunov 混沌，而是"种子 + 每步扰动累积放大"的**可观察行为一致**的近似。

## 四、L2 推进器（六环节）在 V1 的落地

| 环节 | 对应实现 |
|------|---------|
| ①欲望/冲动（内主） | `_choose_domain`：按"先在条件拉偏 + 年龄拉偏"的权重，选出本步主领域 |
| ②外生冲击（外辅） | 同上，PRNG 每次抽取即带随机冲击，与状态拉偏叠加 |
| ③事件 E | `_render_event`：领域 + 先在条件 + 年龄 → 拼出有质感的具体事件 |
| ④后果 C | V1 简化为"直接推进"（真实系统会展开新情境 L'） |
| ⑤反哺 ΔS | `_form_belief`：从该领域"倾向池"挑认识，定强度；避免重复以增厚度 |
| ⑥推进 | `run` 循环年龄采样点（5..target_age，每 5 岁一点，V1 简化） |

## 五、仍待改进（诚实记录）

- **④后果展开**缺失：V1 事件产生认识后，没有真正"把 L 推向新情境"（真实系统需要，是后续重点）。
- **事件→认识的映射仍是候选池人工填**：只验证了"机制可行"，不是"大模型自动生成"（那是 X 接入大模型后的形态）。
- **先在条件候选池极小、手工**：真实系统需接入真实世界知识层。
- **演示脚本存在小瑕疵**：签名输出里 `round(b.strength,3)` 未真正求值、近种子对比输出冗余——属展示层，不影响引擎。

## 六、里程碑意义

V1 证明：**"系统自己孕育一个人"这件事是成立的** —— 只给时代锚 + 种子，系统就能在合法状态格内生发先在条件、推进出一段有质感的人生、长出非标签的人格，且对种子敏感（同种子复现、近种子不同）。这验证的是"诞生"本身，而不仅是"载体"（V0）。
