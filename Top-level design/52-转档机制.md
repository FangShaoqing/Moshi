# 52 · 转档机制（promote）：显式、一次性、原子；正式期**不强制**转档

## 〇、背景与决策
**问题**：原设计"正式版拒绝加载验证期数据"（防污染）→ 意味着验证期积累的信任/记忆/故事
在切正式期时会"推倒重来"。这不合理——**原意是防意外混入，不是丢弃真实关系**。

**决策（协作方确认）**：**能力提供，不强制**——
- 转档**永远显式**（`python -m moshi.promote`），一次性、原子（临时文件 + os.replace，不会写出半个文件）；
- 正式期**默认不拦验证期数据**：可继续运行（只提醒），想严格防污染的用 `--mode-policy strict`；
- **标签随数据出身走**：验证期数据在正式期跑，仍是 verify 标签（不会被悄悄改掉）；
  新数据按运行标签落盘；转档 = 唯一改标签的入口。

## 一、命令
```
python -m moshi.promote --status              # 看各种子标签（production / verify / none）
python -m moshi.promote --seed 12345678       # 指定种子转档
python -m moshi.promote --all                 # 全部转档
```
- 只改 `mode` 字段（state.json / world.json / life.json 三件套）；**她的人格/记忆/信任/故事/日子全不碰**；
- 幂等：已是 production 的种子不动。

## 二、运行策略（qqbot / server）
| 参数 | 行为 |
|---|---|
| `--mode verify`（默认） | 验证期，照旧 |
| `--mode production --mode-policy warn`（默认策略） | **验证期数据继续运行**，打印提醒（"如需正式期标签，执行 promote；她的一切都会延续"）——不强制 |
| `--mode production --mode-policy strict` | 严格防污染：验证期数据**拒绝加载**，提示两条路（promote 延续 / clear 重来） |

## 三、回归（✅ 15 项）
转档三件套全改/幂等/不波及别的种子/不丢数据（历史/故事/标签延续）/
warn 策略继续运行且标签不被悄悄改 / strict 拒绝 / --all / --status。

## 四、意义
- 你现在就可以**放心在 QQ 里认真跟她相处**：验证期积累的一切，将来转档即延续；
- "意外污染"依然不可能：转档是显式操作，不会静默发生；
- 验证期 → 正式期只是"一个随时能跨过去的坎"，不再是"推倒重来"。
